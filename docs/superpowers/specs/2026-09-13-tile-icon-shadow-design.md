# 测试条气球/公文包 tile 阴影与软陶质感统一设计

日期：2026-09-13  
状态：已获用户确认，待实现

## 目标与非目标

### 目标

保持气球与公文包当前主体造型、比例和主题配色不变，将两枚测试条 tile 统一到
`tile-love-v10`、`tile-star-v10`、`tile-mbti-v10` 已使用的资产契约：

- 172×172 画布；
- 主体位于约 148×148 的统一实体框；
- 主体边缘连续抗锯齿；
- 左上光源对应的左/下方向性外部软影；
- 影带延伸到主体外并自然衰减；
- 保留高调奶油软陶的表面颗粒、体积高光和柔和低对比质感；
- 页面继续使用 `filter: none`，避免已烘焙阴影被 CSS 重复叠加。

### 非目标

- 不改变测试中心卡片的布局、尺寸、间距、文字或点击行为；
- 不修改全局 `--shadow-card`、`--shadow-image` 或其它页面的阴影令牌；
- 不为单个页面增加 CSS 阴影特例作为最终方案；
- 不重做 love/star/MBTI 或底栏图标；
- 不把工作区中已有的验证截图、临时脚本和其它未提交改动纳入本任务；
- 不在视觉验收完成前合并到稳定基线或部署。

## 当前问题证据

测试页 `.test-page__card-spot` 当前统一声明 `filter: none`，因为参考 tile 的投影已经
烘焙在 PNG 内。`tile-love-v10` 和 `tile-star-v10` 的 alpha 在实体边界之外继续延伸，
有效影带可到画布底部约 y=171；`tile-fun-v22` 和 `tile-career-v22` 在约 y=165 后
完全结束，主体外没有同级空气影。

v22 还把较强的明暗变化绘制在实体内部，底缘出现白色/暖色硬带。这样会让图标看起来像
贴在卡片上的平板，即使继续调节内翻棱的颜色、峰值或宽度，也不能产生其它图标的浮起感。

当前 `miniapp/src/config/tileShadow.test.ts` 主要检查内翻棱峰位、峰值和“实体外无 alpha
平板”。它没有要求外部影带存在，因此 v22 可以全绿但仍不满足视觉目标。实现时必须拆开
“主体内翻棱”与“主体外空气影”两个契约。

## 方案选择

### 方案 A：仅在页面给 v22 加 CSS `drop-shadow`

不采用。它能快速补一层轮廓影，但无法去除 v22 已烘焙的白色/暖色边带，也不能使表面
纹理与参考 tile 同步；最终会形成 PNG 内部一层、CSS 外部一层的双光照模型。

### 方案 B：保留主体，按参考 tile 重组资产（采用）

以现有气球/公文包主体 RGB 为输入，生成新的 v23 透明 PNG。主体和外部影在生成阶段
分离，再使用 love tile 的 alpha/合成亮度剖面映射同一光向和衰减曲线。这样不改变图标
语义和主要造型，又能修正资产职责不一致的问题。

### 方案 C：重新通过 kit 生图

暂不采用。它可能得到更统一的颗粒和光影，但也可能改变公文包扣件、把手、气球比例
或颜色，需要重新选择和验收；在当前主体已经可用的前提下，风险和成本高于方案 B。

## 资产处理设计

### 输入

- `miniapp/src/assets/illus/tile-fun-v20.png`，固定作为气球主体 RGB 输入；
- `miniapp/src/assets/illus/tile-career-v20.png`，固定作为公文包主体 RGB 输入；
- `miniapp/src/assets/illus/tile-love-v10.png` 作为参考阴影与边缘剖面；
- 现有 `miniapp/art/ref-pages-v3` 处理脚本与 kit 的压缩/抠图约束。

v20 源含有底部 alpha 平板，处理脚本必须先按主体连通区域清除该平板；v22 只作为
视觉回归对照，不得再次作为 RGB、mask 或影层输入。

### 输出

- `miniapp/src/assets/illus/tile-fun-v23.png`；
- `miniapp/src/assets/illus/tile-career-v23.png`；
- 画布固定 172×172；
- 主体实体框与其它测试 tile 对齐：在使用统一主体判据后，宽高与 love/star 的对应值
  各相差不超过 4px，中心点各轴相差不超过 3px；
- PNG 透明区不携带矩形卡底；
- 单图经过 TinyPNG，保持 PNG 格式且 ≤180KB；
- 采用升版文件名，禁止覆盖 v22 原路径。

### 处理步骤

1. **确定主体 mask**：从输入源提取真实圆角 tile 连通区域，过滤旧版底部平板和四角
   外溢；使用超采样/覆盖率生成连续 alpha，避免 78/198 之类的两级台阶。
2. **保留主体材质**：在主体 mask 内保留原有气球、公文包、扣件、把手和 tile 表面
   颗粒；不得用简单纯色填充替换整张主体。
3. **处理内翻棱**：只保留与参考 tile 同级的轻柔主体边缘过渡。不得把整条底缘压成
   高对比深带，也不得再制造白色内衬板。
4. **生成外部空气影**：以 `tile-love-v10` 的主体外 alpha 与合成亮度为参考，提取
   左/下方向的影带；按新主体 bbox 做连续坐标映射，使用覆盖率和颜色合成而不是复制
   固定矩形。
5. **影带合成**：影带位于主体下方，接近主体处较实，向外平滑衰减；左侧影比底部
   更浅，上侧和右侧保持接近页面底色。影带不能反向移动到主体内部。
6. **边缘合成**：主体覆盖影层，保留半透明抗锯齿像素；影层在主体外最多延伸到与
   love/star 相同的有效范围，不能产生长直边或固定宽度矩形尾巴。
7. **压缩与检查**：先在 `prepared/` 输出无损中间图，完成像素检查后走 TinyPNG，
   将压缩结果落到 `src/assets/illus/`。

## 测试设计

### 结构测试

对 fun/career v23 解码后检查：

- 图片尺寸为 172×172；
- 主体 bbox 与其它 tile 的宽高和位置在容差内；
- alpha 边缘有足够的连续等级，不能退化为少数台阶；
- 主体外不存在贯穿画布的矩形 alpha 平板；
- 影带外侧不存在长直横线、固定宽度尾巴或四角残留。

### 视觉剖面测试

以 `tile-love-v10` 为参考，对实体中段采样：

- 下缘主体外存在连续影带，峰值距离与参考在容差内；
- 左缘存在较浅的方向性影带；
- 影带从接触处向外单调或近似单调衰减，不得在更远处重新变深；
- 上缘和右缘保持接近页面底色，不出现全包围的灰边；
- 主体内部的边缘过渡不能替代外部影带，测试必须分别统计“外部 alpha”与“内部亮度”。

剖面容差固定为相对参考值：下缘影带有效末端与 love 相差不超过 2px；下缘外部影的
合成亮度峰值为 love 的 0.75～1.25 倍，峰位相差不超过 3px；左缘峰值为 love 的
0.65～1.30 倍；上/右侧主体外 3px 处的压暗量不得超过页面底色亮度的 5%。TinyPNG
压缩后的最终资产必须重新执行同一组检查，不能只验证未压缩中间图。

### 页面契约测试

- 测试中心和记录页都引用 v23；
- `.test-page__card-spot` 仍为 172rpx 正常文档流元素；
- CSS 仍为 `filter: none`，避免与烘焙影重复；
- 不引入页面特例 shadow class。

## 验证与验收

按以下顺序执行：

1. `npm --prefix miniapp run test -- src/config/tileShadow.test.ts src/pages/test/index.test.ts src/pages/records/index.test.ts`；
2. 运行项目约定的构建命令，生成 fresh `miniapp/dist`；
3. 在微信开发者工具清缓存后预览测试中心和记录页，重点观察四枚 tile 的底部接触影、
   左缘软影、圆角抗锯齿和材质颗粒；
4. 对比 v23 与 love/star 的 1×、2× 截图，确认没有白板、双影、蓝灰脏棱或长直边；
5. 用户完成视觉验收后，再运行完整 `npm run test` 并提交本任务明确触碰的文件。

视觉验收未通过时，优先回到资产处理脚本调整 mask/影带映射，不在页面 CSS 追加临时
特例。暗色主题只需确认透明资产没有黑底或亮边泄漏；本任务不改变暗色 token。

## 风险与回滚

- **风险：主体 bbox 或影带过大**：通过结构测试与 fresh 预览发现后，调整处理脚本参数，
  不修改页面布局。
- **风险：TinyPNG 量化损伤细 alpha**：保留 prepared 无损中间图，若压缩后等级不足，
  降低尺寸前先调整 PNG 量化策略，不能以硬阈值抠图替代。
- **风险：微信缓存 v22**：v23 文件名和引用同时升级，构建后清缓存；不覆盖 v22。
- **回滚**：仅需把两个页面引用回 v22 并保留 v23 作为未使用候选，不删除旧资源，避免
  破坏已有构建或 COS 热更索引。
